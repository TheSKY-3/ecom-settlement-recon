## 8. 自然基线 → P1 注入雷区映射

| 差异类型（雷区） | 自然发生量（本报告口径） | P1 处置 |
|---|---|---|
| 单边账 | 有订单无支付 1；有订单无明细 775；孤儿支付行 0；孤儿明细行 0 | 无明细 775 单样本充足；"已送达但无支付"仅 1 单，作为保留金样本并注入变体 |
| 金额不符 | 少付 209 + 多付 367；支付=仅商品价 0（自然数据不存在该模式） | 自然样本充足；注入时补充"拆单支付/含运费口径"受控变体 |
| 状态不一致 | canceled/unavailable 但有支付 1234 单（269735.11 BRL，1093 单曾审批） | 自然样本作为保留测试集；注入变体：canceled 无支付但账单已开 |
| 退款遗漏 | 自然数据无退款流水表；代理信号 = 取消/不可达单已付额 269735.11 BRL | 退款流水侧需全量合成注入 |
| 重复结算 | 支付键重复 0；明细键重复 0 | 自然几乎为零 → 需全量注入 |
| 版本差异（账单新旧版） | 自然数据不存在账单侧 → 无法自然发生 | 全量注入（对应如祺"新版/旧版账单兼容"） |

## 9. P0 结论

1. 两侧齐全订单的金额一致率 99.42%（98089/98665）；自然不一致 576 单（0.58%），多付 367 单、少付 209 单；其中 477/576 单差异在 10 BRL 以内（分位尾差形态），10 BRL 以上大额差异是真实异常样本。
2. 单边账形态：无明细 775 单（集中在 canceled/unavailable，含 1 单 shipped 无明细）、无支付仅 1 单且状态为 delivered；孤儿支付/明细 0，说明该数据集对 orders 的引用完整性良好，单边账注入需自行构造。
3. 取消/不可达但已支付 1234 单（269735.11 BRL，1093 单曾审批）是最大的自然差异面，可直接用作"状态不一致/退款遗漏"的 ground truth 种子。
4. 重复结算（支付/明细键零重复）与版本差异（无账单侧）在自然数据中不存在，是纯注入区；退款遗漏需合成退款流水表（P1 设计）。
5. 结构冻结：原始层 schema 见 `sql/01_schema.sql`（无约束原始层，重复键不丢行）；已知数据特性：product_category_name_translation.csv 带 BOM（加载已兼容）、789 条重复 review_id、2 条分期=0 的 credit_card 行、3 条 not_defined 零额支付行。
