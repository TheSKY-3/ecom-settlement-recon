## D010 工作台技术栈：FastAPI + 原生前端 + 手写 CSS（2026-09-26）

- **问题**：界面用什么做？视觉风格抄谁？
- **备选**：Streamlit（最快但样式模板化、答辩时"一眼 Streamlit"）/ FastAPI+静态页（多写点代码）/ 前端构建链 React+Tailwind（最漂亮但加一整套工具链）。
- **选了**：FastAPI + 静态 HTML + 原生 JS + 手写 CSS，零前端依赖；视觉走调研结论里 2026 年数据工具的主流——shadcn/ui / IBM Carbon 一脉的"低装饰、中性色、密集数据表、颜色只表状态"，等宽数字，详见[工作台设计文档](superpowers/specs/2026-09-26-workbench-design.md)第 4 节。
- **为什么**：与兄弟项目同栈（FastAPI+Pydantic 契约），经验可复用、面试叙事连贯（"两个项目同一套受约束工作台模式"）；无构建链意味着改样式不用装 Node，初学者改得动；手写 CSS 篇幅可控（约 400 行）却完全贴合对账"密集表"场景。Streamlit 被否的另一原因：表格交互（筛选/翻页/行点开对照）在它里面绕着框架走。
- **何时推翻**：若 P3 后需要复杂交互（多面板联动、实时流），再评估引入构建链；接口层（JSON 契约）已定死，前端可整体替换。

## D009 产品形态补一笔：加本地 Web 工作台，exe 只当启动器（2026-09-26）

- **问题**：原定"不做网页界面"（D005），现在用户拍板要界面，做成什么样？
- **要求**：① 双击 `对账工作台.exe` 直接能用；② exe **只是启动器**，不把应用和数据打进 exe；③ 好用、可落地优先。
- **选了**：本地 Web 工作台——启动器 exe（几 MB，只负责拉起 `.venv` 的 Python 服务并自动开浏览器）+ FastAPI 本地服务（只监听 127.0.0.1）+ 静态页面。关掉控制台窗口即停止。
- **为什么**：exe 打包整套（兄弟项目的 pywebview 路线）体积大、换机器要重打包、杀软易误报；薄启动器把"打包物"缩到最小，代码和数据留在项目里，改完代码刷新浏览器就生效。作品集场景"现场演示"用浏览器也最稳。
- **何时推翻**：若需要离线单文件分发给非本机用户，再评估 pywebview 整包路线。

## D008 注入数量与佣金费率定稿（P1 冻结值，2026-09-26）

- **问题**：考卷出多少题、按什么费率造账单？
- **选了**：六类共 **1,750 颗雷**（删账单 400 / 孤儿账单 100 / 删支付 200 / 费率错 250 / 漏运费 250 / 取消单开账单 150 / 退款缺失 200 / 重复 100 / 版本差异 100）；佣金统一 **0.20**，错误费率 0.10，旧版费率 0.15。
- **为什么**：总雷量约为干净账单的 1.8%——够评测用又不至于"遍地是错"失真；费率本身不追求真实（Olist 真实费率不公开），引擎抓的是"与规则卡不符"，不是"与行业不符"。
- **何时推翻**：P4 评测前可调（改 `src/synth/config.py`），但改 = 重出考卷 = 必须重新冻结并在本文件留档；`tests/test_config.py` 会把未经立项的改动挡下来。

## D007 记录规矩：讲明白版写作法（2026-09-26）

- **问题**：项目记录怎么写，才能既让初学者看懂、又能在面试时复述？
- **备选**：工程式文档（术语随便用）/ 讲明白版。
- **选了**：讲明白版——每篇解释固定四段（卡在哪 → 做了什么 → 不这么做会怎样 → 面试怎么说，结尾附"面试官再追问怎么接"）；一篇只讲一个决定，必带真实数字；正文黑话只留个名，格式"人话（黑话）"，"什么时候会用到"集中放术语卡，一行打住；事实、决定、猜测、卡点分开写；估算标明"这是估算"。
- **为什么**：这套规矩在电商AGENT项目里验证过——读者就是项目主人自己，目标是能对着面试官复述。
- **何时推翻**：不推翻，只迭代格式。

## D006 Agent 框架：自研薄循环，不用现成框架（2026-09-26）

- **问题**：AI 归因/查账的"思考→调工具→看结果→再思考"循环，用现成框架（LangGraph）还是自己写？
- **备选**：LangGraph / 自研约 300 行 / 原生接口裸写。
- **选了**：自研受约束循环。
- **为什么**：本项目 AI 只出现在两个受控出口（歧义归因、自然语言查账），单任务最多 8 步、5-6 个工具，框架的重能力（断点恢复、人工介入）用不上；自己写每行护栏（白名单/预算/留痕/查引用/失败就说不知道，五件套），面试深挖讲得清；与电商评论项目（用框架）形成"会用框架 → 懂框架底下是什么"的递进叙事。
- **何时推翻**：P3 若发现需要多轮人工介入等重能力，换 LangGraph——接口已锁死为 `attribute(差异)` 和 `ask(问题)` 两个函数，引擎层一行不用改。

## D002 金额容差 ±0.005 雷亚尔（2026-09-26）

- **问题**：两笔金额差多少算"对得上"？
- **选了**：±0.005（即比较到"分"，实际是浮点数比较的精度处理）。
- **为什么**：巴西货币雷亚尔最小单位是分；盘点显示自然数据里 477/576 的差异在 10 雷亚尔以内（多为分位尾差），容差定在分位能抓住真实错误、放过四舍五入噪音。
- **何时推翻**：P4 评测若发现大量 1 分位的"假差异"误报，升到 ±0.01 并记录影响。

## D001 原始数据库不设唯一约束（2026-09-26）

- **问题**：数据库建表要不要给订单号等加"唯一"约束？
- **选了**：一律不加，只建索引。
- **为什么**：约束会**静默丢掉**重复行——但对账项目里，重复本身就是要测量的错误（P0 实测：评价表有 789 条重复编号，支付/明细表为零）。加载层丢数据 = 评测地基歪了。唯一性交给对账引擎当异常报告。
- **何时推翻**：基本不会；对账结论层（非原始层）可以建约束。
