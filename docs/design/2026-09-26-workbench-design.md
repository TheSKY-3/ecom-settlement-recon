# 设计文档：对账工作台（本地 Web UI + 启动器）

> 日期：2026-09-26。状态：依据用户 2026-09-26 指示成文（"要一个基本可落地、好用的界面；exe 只当启动器不打包全部内容；美术风格上网调研后定"）。
> 本文取代原设计文档第 1 节"非目标：不做网页界面"（原决定已推翻）。

## 0. 一分钟版

给对账项目加一个**本地网页工作台**：双击项目根目录的 `启动对账工作台.bat`（或 `对账工作台.exe`），它只干一件事——拉起本机 Python 服务并自动打开浏览器。页面展示冻结评测集的概览（三本账行数、1,750 条预埋差异的六类分布）、标准答案浏览（筛选/搜索/翻页）、单条差异的三本账原始行对照。引擎、Agent 出结果后，都以 JSON 接口的形式接进这套页面，界面骨架不变。

## 1. 目标与非目标

**目标**
1. 双击 `启动对账工作台.bat`（或 `对账工作台.exe`）即可用：启动器只负责拉起 `.venv` 的 Python 服务并开浏览器，**不打包应用代码和数据**（换机器/改代码不需要重新打包）。
2. 三个页面：概览（数字卡片 + 六类分布条形图）、标准答案浏览（表格 + 筛选 + 翻页 + 单雷证据对照）、关于（架构与路线）。
3. 视觉风格按调研结论执行（见第 4 节），浅色、密集表、中性色 + 单一强调色。
4. 全部接口有类型约定（Pydantic 模型），引擎/Agent 接入时接口风格一致。

**非目标**
- 不做登录、多用户、部署上线——这是单机本地工具，只监听 127.0.0.1。
- 不做前端构建链（React/npm/Tailwind）——静态 HTML+CSS+原生 JS，改一行存一行。
- 本期不接引擎结果（引擎交付后替换 `/api/diffs` 的数据源即可）。

## 2. 总体架构（对账项目四层 + 启动链路）

```
┌─ 数据层（只读）────────────────────────────────────┐
│ data/olist.db + data/synthetic/{clean,dirty}/*.csv │
└──────────────┬─────────────────────────────────────┘
               ▼
┌─ 引擎层（待建）：matcher → classifier → audit ───────┐
└──────────────┬─────────────────────────────────────┘
               ▼
┌─ Agent 层（待建）：attribute() / ask() ──────────────┐
└──────────────┬─────────────────────────────────────┘
               ▼
┌─ 工作台（本次交付）：FastAPI + 静态页面 ──────────────┐
│ GET /                静态页（HTML+CSS+原生 JS）      │
│ GET /api/overview    评测集概览统计                  │
│ GET /api/diffs       标准答案筛选/翻页               │
│ GET /api/diffs/{id}/ledger   单条差异三本账原始行    │
└─────────────────────────────────────────────────────┘

双击 启动对账工作台.bat（或对账工作台.exe，仅几 MB 的启动器）
  → 找到 .venv\Scripts\python.exe，新开控制台窗口跑 python -m src.workbench.serve
  → 服务监听 http://127.0.0.1:8770，自动打开默认浏览器
  → 关闭控制台窗口 = 停止服务
```

分工原则与原设计一致：界面只**读**，不写数据；一切结论来自确定性管道，界面不二次计算。

## 3. 页面与接口契约

**页面（单页应用，前端 hash 路由 `#/overview` `#/diffs` `#/about`）**
- 概览：KPI 卡片（干净/脏三本账行数、标准答案总数、种子号）+ 六类差异分布条形（纯 CSS，无图表库）+ 建库时自然差异基线静态数字（注明来源与日期）。
- 标准答案：表格列 = gt_id / 订单号 / 类型 / 变体 / 目标侧 / 描述；筛选（类型下拉、目标侧、关键词搜订单号或描述）+ 分页（每页 50）；点行弹出该订单的三本账原始行对照（账单、支付、退款、订单、明细）。
- 关于：四层架构图（本文件第 2 节）+ 里程碑状态 + 红线提示。

**接口（全部只读 GET）**

| 路由 | 返回（Pydantic 模型） | 说明 |
|---|---|---|
| `GET /api/overview` | `Overview` | 数据集统计 + gt 分类计数 + 种子 |
| `GET /api/diffs` | `DiffsPage` | 参数 `type, side, q, page, page_size(≤200)` |
| `GET /api/diffs/{gt_id}/ledger` | `LedgerView` | 该订单在账单/支付/退款/订单/明细五处的原始行 |
| 静态 | — | `/` 与 `/static/*`，缺文件返回 404 不抛 500 |

## 4. 视觉风格（调研结论 → 我们的选择）

调研结论（2026-09，来源见 README"参考"）：后台/数据工具的主流是 **shadcn/ui 与 IBM Carbon 一脉**——低装饰、中性灰阶、单一强调色、颜色只用于状态语义、等宽数字、密集数据表为主角；财务/对账类工具额外强调"异常优先"布局（先把对不上的放前面）与并排对照视图。

**我们的选择：「中性密集数据台」**
- 浅色主题：底 `#fafafa`、卡面纯白、边框 1px `#e4e4e7`、圆角 8px、几乎不用阴影。
- 文字 `#18181b`，次级 `#71717a`；强调色只一个：蓝 `#2563eb`（链接、当前页签、主按钮）。
- 金额与 ID 用等宽字体 + 表格数字对齐（`font-variant-numeric: tabular-nums`）。
- 六类差异各配一个低饱和徽章色（语义色只出现在徽章与状态点，不大面积铺）。
- 中文字体栈 `system-ui, "Microsoft YaHei", sans-serif`，正文 14px，表格 13px。
- 不引任何前端依赖：无 Tailwind、无 React、无图表库；一个 `style.css` + 一个 `app.js`。

## 5. 启动链路与失败处理

- `launcher/launcher.py`（用 PyInstaller 打成 `对账工作台.exe`，仅此一个文件进 exe）：定位 exe 所在目录 = 项目根 → 校验 `.venv\Scripts\python.exe` 存在 → 以独立控制台窗口启动 `python -m src.workbench.serve --open-browser`（环境变量注入 `PYTHONUTF8=1` 防中文日志乱码）→ 启动器自身退出。venv 缺失时弹控制台提示后暂停退出，不报"无响应"。
- 服务绑定 127.0.0.1:8770（端口被占自动 +1 重试至 8779）；`--open-browser` 在服务就绪后打开浏览器。
- 数据文件缺失：接口返回明确错误信息（缺哪个文件、去哪个目录、跑哪个脚本补），不抛裸异常栈。
- 同一启动器脚本同时提供 `启动对账工作台.bat`（不打包也能双击，便于开发期用）。

## 6. 测试策略

- 数据模块（`src/workbench/data.py`，纯标准库 csv/sqlite3）：临时目录造小 CSV → 验证统计、筛选、分页、ledger 查找；绝不依赖真实数据文件（真实文件 gitignore，测试机可能没有）。
- 接口（FastAPI TestClient）：状态码、字段形状、筛选正确性、未知 gt_id → 404、静态页 200 且含标题。
- 启动器：exe 打包后冒烟——启动 exe → 3 秒内 `GET /api/overview` 返回 200 → 杀进程。
