## 1. 目的

给对账引擎出一张"有人为错误、且每个错误都有标准答案"的考卷。干净世界（无错）与脏世界（埋雷后）同时产出，评测时：引擎跑脏世界 → 输出差异报告 → 对照 `ground_truth.csv` 判检出率/误报率/归因准确率。

## 2. 干净世界规则（规则卡）

| 编号 | 规则 | 参数 |
|---|---|---|
| R1 | 平台账单只开给"有明细且状态不是 canceled/unavailable"的订单 | — |
| R2 | 应付卖家 = 货款 + 运费 − 佣金（佣金 = 费率 × 货款） | 佣金费率 **0.20**（可配置，见 open-questions） |
| R3 | 取消/不可达且支付已审批的订单，全额退款（金额 = 支付合计） | — |
| R4 | 账单日期 = 审批日 +7 天（缺审批用下单日）；退款日期 = 审批日 +14 天 | 偏移天数可配置 |

## 5. 隔离规则（保证每颗雷唯一归因）

1. **池互斥**：一个订单最多中一种雷（`allocate_pools` 不放回抽样）。
2. **避开自然差异**：P0 盘出的金额不一致 576 单不进任何雷池——引擎报出的这些差异属于"自然差异"对照组，不算合成雷。
3. **孤儿账单编号**：随机 32 位十六进制、与真实订单号空间一致但不冲突（模拟"上游传错单号"）。
4. **只动三本账的账单/支付/退款侧**，订单与明细表保持原样。

## 6. 引擎（P2）对账时的判分约定

- 引擎应报出的"合成差异"= 与 ground_truth 匹配的差异（按 order_id + diff_type）。
- 引擎报出但 gt 没有的 = **误报**（含 P0 的自然差异——自然差异单独统计，不算误报也不算检出）。
- gt 有但引擎没报的 = **漏检**。

## 7. 变更纪律

- 数值都长在 `src/synth/config.py`；改数值 = 改考卷 = 必须重新冻结并在 decisions.md 记一条。
- 测试 `tests/test_config.py` 把冻结值钉死：任何"顺手调整"都会把测试弄红。

## 8. v1.1 修订（2026-09-26，P2 全量跑分暴露两处考卷缺陷）

1. **漏运费雷必须避开零运费订单**：明细运费合计为 0 的订单埋"漏运费"= 把 0 改成 0，雷物理上不可判（P2 首跑漏检 2 条即此因）。修复：`allocate_pools` 的漏运费池只从运费 > 0 的订单抽取，且注入器加硬校验（遇零运费直接报错）。同类候选池充足（零运费单极少），六类数量不变。
2. **自然差异口径补全**：P0 的"有明细、非取消、却零支付"单（1 单）此前不在自然集合里，引擎如实报"删支付"会被误计入真误报。修复：判分器自然集合 = 金额不符口径 ∪ 零支付口径。
3. 隔离规则第 2 条的"576 单"按 P0 报告口径书写；SQL 直查为 574 单（2 单为四舍五入口径差），判分以 SQL 实际结果为准。雷池总量、六类数量、产物行数与 v1 完全一致；雷的**成员**有变（漏运费池换了 2 单，连带其后抽取的重复/版本池成员平移），故整卷重新冻结为 v1.1。
