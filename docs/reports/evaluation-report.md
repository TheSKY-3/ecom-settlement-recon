# 评测总报告：电商结算对账 Agent（ecom-settlement-recon）

> 2026-09-26。本文是项目全部量化结论的唯一入口；明细分别见
> [P2 引擎成绩单](p2-engine-report.md)、[P4 BenchRec 跨域成绩单](p4-benchrec-report.md)。
> 对外语径：**本地原型 + 合成数据评测**，不涉及任何真实公司数据。

## 1. 一句话结论

同一套**确定性对账思想**（多键分桶 + 容差 + 宁缺勿错 + 审计留痕）在两个域、两份考卷上跑通：
在自家冻结考卷上**全部 1,750 颗人工差异 100% 检出、真误报 0**；在真实银行对账基准
BenchRec 上**精度 99.67%，全面超过官方 ChatGPT 基线**，1 秒判完 3.2 万笔。AI（LLM）
只出现在两个受约束出口做语言组织，答案数字全部过白名单校验。

## 2. 评测体系（为什么可信）

| 设计 | 做法 | 防的是什么 |
|---|---|---|
| 合成考卷 + 冻结 | 六类九变体 1,750 颗人工差异埋进真实 Olist 底座（9.9 万单），种子固定、注入规范成文（v1.1） | "换引擎改分数"——所有引擎改动考同一套题 |
| 每颗雷可判定 | 造数器自校验 + 注入器硬校验（如漏运费雷禁止落在零运费单） | "带病考卷压低分数上限"（D011 事故后立此制度） |
| 自然差异分桶 | P0 盘点出 575 条数据自带的金额不一致，判分时单独立桶不计误报 | "把数据本身的错算成引擎误报" |
| 独立验证器 | 引擎结论由第二套代码不读结论、只凭原始数据重推 | "引擎自说自话" |
| 审计链 | 每步输入输出 SHA-256 指纹环环相扣，篡改即断链 | "结果不可复现/被悄悄改过" |
| 跨域复跑 | 同一匹配思想接 BenchRec（真实银行数据），复刻竞赛判分口径，与官方 ChatGPT 基线同台 | "只在自己造的数据上好用" |

## 3. 主战场成绩（Olist 三方对账：平台账单 × 订单 × 支付）

| 指标 | 数值 | 说明 |
|---|---|---|
| 考卷规模 | 干净/脏三本账各约 9.8 万行 + 1,750 颗雷 | 六类：单边账 700 / 金额不符 500 / 退款遗漏 200 / 状态不一致 150 / 重复结算 100 / 版本差异 100 |
| 检出 recall | **100%（1,750/1,750）** | 六类逐类全中 |
| 真误报 | **0** | 575 条 FP 全部为 P0 自然差异（单独分桶） |
| 全量耗时 | 约 2.5 秒 / 9.9 万单 | 纯标准库，无 AI |
| 引擎发现 | 2,325 条 = 1,750 雷 + 575 自然差异 | 逐条过独立验证器 + 审计链 |
| Agent 护栏 | 168 测试全绿；真模型实测：答案数字全过白名单、缺信息如实说"事实单未提供" | AI 只在 attribute/ask/chat 出口 |

## 4. 跨域成绩（BenchRec 银行现金对账，真实数据 CC BY 4.0）

32,048 笔银行流水 × 37,123 条内部分录，任务 = 为每笔流水找出分配键（可多分配、可无匹配），
判对 = 预测分配集合 ⊆ 真值集合（宁缺勿错，竞赛口径）。

| 提交 | 精度 | 覆盖率 | 总判对率 |
|---|---|---|---|
| **确定性引擎（本项目）** | **99.67%** | **84.6%** | **90.4%** |
| 官方 ChatGPT 基线 | 95.20% | 64.9% | 65.2% |

- 耗时 1.0 秒（纯标准库）；竞赛硬门槛 99.8%，当前差 **0.13pp**。
- 已知边界（诚实声明）：89 个错配已归因——46 个为"唯一金额候选无印证即配"（含官方标注的
  0.2% 标签噪声场景）、11 个来自 265 条同金额的超大厅；"参考号字面印证"方向已被实验证伪
  （B/A 是不同编码体系）。改进方向（占用约束 / attributes 长编码印证 / train 学阈值）见成绩单。
