## 2. 60 秒电梯版

"我做过财务对账自动化，深知对账两个痛点：错账要一笔笔人工找，结论没人敢信。这个项目我
把实习经验抽象成一个可复现的对账 Agent：先用真实电商数据做底座、人工埋 1,750 颗六类差异
当冻结考卷；核心引擎是纯规则的确定性匹配——多键分桶加容差，2.5 秒全量判卷，考卷上满分、
零误报；再拿到一个真实的银行对账基准上跨域验证，精度 99.67%，超过那个基准官方的 ChatGPT
方案。AI 只用在最外层：给差异写人话归因、回答自然语言查账，而且每个数字都要能对回账本，
对不回就自动降级成模板。整个项目 90 个测试全离线可复现，双击 exe 就能演示。"

## 3. 三分钟展开版（STAR）

- **S 背景**：实习做过月度对账（部门实测约 1 天 → 约 10 分钟），方法可复用但工具不可带
  走、结论不可复现是两大遗憾。
- **T 任务**：做一个"结论可信、可量化、能换域"的对账 Agent——不是演示玩具，是评测驱动
  的工程。
- **A 行动**（按因果链讲，每步一个决策）：
  1. 先摸底：真实电商数据里"天然"有多少对不上的账（99.42% 一致率，576 单自然差异）——
     不先划清天然错，人工埋的雷就无法判分。
  2. 造考卷：按注入规范埋六类差异、冻结种子——所有引擎改动考同一套题，分数才可比。
     考卷还出过一次事故：漏运费雷埋在零运费单上物理不可判，整卷重冻结（D011）。
  3. 写引擎：规则树九变体 + 独立验证器 + SHA-256 审计链——确定性优先，LLM 不碰主匹配
     路径（不可复现、不可审计、贵、慢）。
  4. 上 AI：LLM 只做两件事——差异归因解释、自然语言查账；答案数字过白名单校验，
     违规自动重写一次，再违规降级为模板文案。
  5. 跨域验证：银行对账基准 BenchRec，同一套匹配思想 1 秒判完 3.2 万笔，精度 99.67%
     超官方 ChatGPT 基线（95.20%）。
  6. 交付：FastAPI 工作台 + 7MB 薄启动器 exe，界面只读、AI 受约束，90 测试全离线。
- **R 结果**：见上方数字弹药库；成果包括两份成绩单、12 条决策记录、总评测报告。

## 5. 深挖问答预案

1. **为什么不用 LLM 做匹配？** 匹配要求可复现、可审计、可判分——LLM 三样都不占；且
   BenchRec 基线证明纯规则在同领域显著强于 LLM 方案。LLM 的价值在"组织语言"，不在"找账"。
2. **为什么自己造考卷而不是只用真实数据？** 真实数据没有完整标准答案就没法算 recall/
   precision；人工埋雷 + 冻结才有可比性。同时保留真实底座与真实基准（BenchRec）兜住
   真实性，两层证据互补。
3. **AI 幻觉怎么防？** 三道闸：提示词限定"只能用事实单"；输出白名单校验（每个数字/编号
   必须能在证据里找到，违规重写一次）；再违规降级为确定性模板。评测全程离线假模型，真模型
   只冒烟。
4. **跨域差 0.13pp 怎么回事？** 89 个错配已归因：最大一类是"金额唯一候选无印证即配"，
   且含数据集官方标注的 0.2% 标签噪声；改进方向已列（占用约束/长编码印证/学阈值），
   未做是因为边际收益低于收束期交付。
5. **数据是真的吗？** 底座是 Kaggle 公开电商数据集（Olist，CC 许可），平台账单/退款流水按
   公开规则卡合成；跨域考卷是 ICAIF 2023 真实银行基准（CC BY 4.0）。不用任何公司真实数据。
6. **exe 为什么只有 7MB？** 薄启动器：只拉起本机 Python 服务并开浏览器，代码数据留在
   项目目录——改完代码刷新即生效，换机不用重打包，也避免整包体积与杀软误报。
7. **怎么保证结论没被改过？** 每步输入输出 SHA-256 指纹环环相扣（审计链），篡改即断链；
   结论还要过独立验证器重推。
8. **如果给你真实业务数据会怎么落地？** 换规则卡（费率/容差/状态机）与键映射，考卷流程
   原样重走：先盘点自然差异 → 冻结基线考卷 → 引擎出分 → 迭代。工作量在业务口径梳理，
   不在架构。
